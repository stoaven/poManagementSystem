# 货运订单费用管理 · 界面原型

高保真静态原型，用于确认布局、字段与交互结构，不是实现代码。
打开 `index.html` 即可（无需构建、无需依赖）。

## 怎么看

| 地址 | 页面 |
|---|---|
| `index.html#/login` | 登录页 |
| `index.html#/shipments` | 货运订单列表 |
| `index.html#/shipment-detail` | 货运订单详情（费用信息录入主战场） |
| `index.html#/shipment-detail/modal` | 新增费用信息弹窗 |
| `index.html#/options` | 选项维护（九类可选值） |
| `index.html#/users` | 用户管理 |

左侧导航可直接切换；点列表第一行进入详情；详情页点「新增费用信息」打开弹窗；
`Esc` 关闭弹窗。选项页的页签与启用开关可交互。

## 视觉语言：多联单

取自货运单据的传统形态——一张单据按白联、粉红联、蓝联、绿联分联打印。
这个来源直接对应系统的信息结构：**一条费用信息同时有应付侧与应收侧，且两侧币种可能不同**。

| 联次 | 颜色 | 用途 |
|---|---|---|
| 白联 | `#FFFFFF` | 表格与表单的纸面 |
| 粉红联 | `#A3304F` | **应付侧** |
| 蓝铅 | `#1B6A85` | **应收侧** |
| 绿联 | `#2E7D5B` | 已完成 / 启用 |

两侧之间用一道竖线分隔（账簿的中缝）。颜色是**语义**而非装饰：扫一眼即知哪半边是应付、哪半边是应收，
且两侧的金额永远不会被混读。

## 设计要点

- **数字一律等宽**（`tabular-nums`）。金额、单号、日期、时间全部用等宽字体并按小数点对齐——
  数据密集的内部系统里，这是账簿质感而不是装饰。
- **所有字段标签中英双语**：上行中文标签，下行英文。覆盖**表格列头、筛选栏标签、表单字段标签、
  分组标题、合计带标签**。英文取**上游字段名**而非意译——
  `Shipment No.`、`Job No.`、`Charge Code`、`Description`、`Department`、`Branch`、
  `Cost Currency`、`OS Cost Amt`、`Cost Tax ID`、`Creditor`、`Sell Currency`、
  `OS Sell Amt`、`Debtor`、`Inv. Type`。上游没有对应字段的（状态、创建人、创建时间、权限、排序）用自然英文名。
  英文一侧因此成了一张「上游字段对照表」：与上游核对时，界面上看到的英文就是对方表里的列名。
  英文用等宽字体、灰一档，不与中文争视觉重量。
- **什么保持中文**：按钮（保存、查询、删除）、状态与权限等**数据值**（已完成 / 管理员）、页面标题。
  这些是「做什么」「是什么」而非「哪个字段」，双语化不增加信息量，反而拉长每处文案。
- **没有客户字段**：往来单位在每条费用信息的应付对象（Creditor）/ 应收对象（Debtor）上，
  货运订单层面不再重复存一个客户。
- **关联收费用**：一条费用信息若满足「应付分支机构 `SHL` 且应收对象 `CNSHO`」，或对称的
  「应付分支机构 `SHO` 且应付对象 `CNSHL`」，行操作里会出现「新增关联收费用」——点击即生成
  并落库一条关联记录：费用代码与应付部门复制源记录，币种与金额取源记录的对侧，另一侧留空待填。
  由本规则生成的记录带「关联」标记，不再提供该操作（否则会链式生成下去）。
- **描述 / 应付税率 / 账单类型三个字段已删除**，因此对应的三张选项表（descriptions、
  cost_tax_ids、inv_types）也一并去掉，选项从九类减为六类。
- **费用信息没有「已结算金额」**：上游字段集里只有 `OS Cost Amt` 与 `Local Cost Amt`，
  没有已结算金额，因此系统也不跟踪「这笔钱收了一半」——支付状态这类概念本期不存在。
  本地金额（`Local Cost Amt`）字段位保留但本期不计算。
- **统一的审计字段**：所有数据表都带**操作人（手机号）、创建时间、更新时间**三件套，字段名与类型
  完全一致。列表页把这三项摊开显示：操作人一栏用等宽字体灰一档，与业务字段区分开。
  选项项不再有排序值——候选列表按代码顺序即可，排序是维护页的负担而不是使用页的需要。
- **左侧是装订边**，边缘打装订孔，选中项像一页纸插在装订线上。全局唯一的装饰性元素，其余一律克制。
- **表格是账簿页**：发丝线、无卡片、无圆角、无阴影、无渐变。
- **币种与金额同格**，用小方框标签贴在数字左侧，一眼知道这个数是什么币。
- **列表页只管定位，不管金额**：货运订单列表只显示单号、条数、状态、操作人与时间；
  金额在订单详情页看（按币种分组的应付/应收合计）。列表页的「应付金额区间」筛选仍可用——
  它作用在订单在指定币种下的合计上。
- **本地金额字段本期不计算**，因此不出现——在录入弹窗底部用一句话说明原因。

## 与规格的对应

字段、校验规则、权限边界均来自 `openspec/changes/add-shipment-management-mvp/`：

- 费用信息 12 个字段 → 详情页表格的应付带（4 列）与应收带（2 列）+ 费用代码、任务码
- 宽表的**操作列固定在右侧**：12 列在笔记本宽度下放不下，横向滚动时行操作必须始终可点
- `Department` / `Branch` 是**应付侧**字段（应付款部门 / 应付款分支机构），因此在录入弹窗里归入「应付」组
- 选项九类 → 选项维护页的九个页签；应付部门初始值 `FIS` / `FES` / `FIA` / `FEA`
- 手机号即凭证（无密码无验证码）、admin / normal 两级权限 → 登录页只有一个手机号输入框；左侧导航底部的用户卡片；选项维护与用户管理仅 admin 可见
- 本期不做汇率折算 → 汇总按币种分组，不给跨币种合计，也不给净额
