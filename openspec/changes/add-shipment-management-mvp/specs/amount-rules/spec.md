# Spec Delta

## Purpose

定义单条费用信息所承载的金额与币种的取值口径：金额精度、应付与应收的币种各自独立。本期不做汇率折算，所有金额都以其自身币种计价，界面不提供任何跨币种的合计或净额。

## ADDED Requirements

### Requirement: 金额精度

系统 SHALL 以两位小数的定点精度存储应付金额与应收金额。请求中金额超过两位小数的输入 MUST 被拒绝，金额上限为 999999999999.99，负数金额 MUST 被拒绝。

#### Scenario: 拒绝超过两位小数的金额

- **WHEN** 用户提交应付金额 100.125
- **THEN** 系统拒绝保存并说明金额最多两位小数

#### Scenario: 保留两位小数

- **WHEN** 用户提交应付金额 100.10
- **THEN** 系统按 100.10 存储并在接口响应中原样返回

#### Scenario: 拒绝负数金额

- **WHEN** 用户提交负数的应付金额或负数的应收金额
- **THEN** 系统拒绝保存并说明金额不能为负

#### Scenario: 允许零金额

- **WHEN** 用户提交金额为 0
- **THEN** 系统接受并保存

### Requirement: 应付与应收的币种各自独立

系统 SHALL 在每条费用信息上分别记录应付币种与应收币种。两者 MUST 取自币种选项表中启用且未被软删除的项，MUST NOT 要求相同。一条记录的应付金额以其应付币种计价，应收金额以其应收币种计价，两者的数值之间不存在换算关系。

#### Scenario: 两侧币种不同

- **WHEN** 用户创建一条应付币种为 USD、应收币种为 CNY 的费用信息
- **THEN** 系统接受并保存该记录

#### Scenario: 两侧币种相同

- **WHEN** 用户创建一条应付币种与应收币种相同的费用信息
- **THEN** 系统接受并保存该记录

#### Scenario: 引用无效币种

- **WHEN** 用户提交的应付币种或应收币种不在币种选项表中，或该项已被停用或软删除
- **THEN** 系统拒绝保存并说明该币种无效
