# Spec Delta

## Purpose

维护费用信息所引用的六类选项数据。每一类选项独立成表，结构相同——有唯一代码、名称、启用状态，并可被软删除。费用信息以**选项内容的字符串**保存这些取值，而选项表是页面下拉的唯一数据来源；系统的增删改查与启停用都作用在选项表上。

## ADDED Requirements

### Requirement: 选项维护的权限要求

系统 SHALL 仅允许管理员（admin）执行选项数据的写操作，包括新增、编辑、删除与启用停用。非管理员（normal）调用这些操作时，系统 MUST 拒绝并返回 403。选项数据的读取（候选列表） MUST 对所有已认证用户开放。

#### Scenario: 管理员维护选项

- **WHEN** 管理员新增、编辑、删除或启停用某项选项
- **THEN** 系统接受该操作并保存变更

#### Scenario: 非管理员尝试维护选项

- **WHEN** 普通用户尝试新增、编辑、删除或启停用某项选项
- **THEN** 系统返回 403 并拒绝该操作
- **AND** 该选项的数据保持不变

#### Scenario: 非管理员读取候选列表

- **WHEN** 普通用户请求某类选项的候选列表
- **THEN** 系统返回该列表，不做权限拦截

### Requirement: 选项表的种类与结构

系统 SHALL 维护六类选项：费用代码、应付部门、应付分支机构、币种、应付对象、应收对象。每类选项 MUST 独立成表，结构相同：唯一代码、名称、启用状态、status（0 正常 / 1 已删除），以及操作人、创建时间与更新时间。选项项的代码 MUST 在其所属选项表内唯一。名称可省略，省略时 MUST 以代码作为名称。选项项的代码一经创建 MUST NOT 被修改，只允许修改名称。

#### Scenario: 六类选项各自独立

- **WHEN** 用户在费用代码中新增一项「FRT」
- **THEN** 该项不出现在币种、部门或其它任何选项表中

#### Scenario: 同一选项表内代码唯一

- **WHEN** 用户在部门选项中新增代码为 `FIS` 的项，而该表已存在代码为 `FIS` 的项
- **THEN** 系统拒绝新增并说明该代码已被使用

#### Scenario: 名称缺省时用代码

- **WHEN** 用户新增选项项时只填写了代码而未填写名称
- **THEN** 该项的名称以代码呈现

#### Scenario: 代码不可修改

- **WHEN** 用户尝试把某选项项的代码改成另一个值
- **THEN** 系统拒绝该修改并说明代码不可更改
- **AND** 该选项项的代码保持不变

### Requirement: 选项数据的增删改查

系统 SHALL 提供选项数据的创建、编辑、删除与查询能力。查询 MUST 区分「管理列表」与「候选列表」两种用途：管理列表展示指定选项表的内容并可按需包含已停用与已软删除的项；候选列表仅包含启用且未被软删除的项，且 MUST 支持按代码或名称的关键字过滤。

#### Scenario: 新增选项项

- **WHEN** 管理员在某选项表中提交一个未占用的代码与名称
- **THEN** 系统创建该选项项并返回其代码、名称与启用状态

#### Scenario: 编辑选项项名称

- **WHEN** 管理员修改某选项项的名称
- **THEN** 系统保存修改并更新最后修改时间

#### Scenario: 管理列表可见已停用与已删除项

- **WHEN** 管理员打开管理列表并请求包含已停用与已软删除的项
- **THEN** 系统返回这些项并标明它们各自的状态

#### Scenario: 候选列表不含停用与已删除项

- **WHEN** 某选项表中存在被停用或被软删除的选项项
- **THEN** 它们不出现在候选列表中

#### Scenario: 候选列表按关键字过滤

- **WHEN** 用户以关键字过滤候选列表，该关键字出现在某选项项的代码或名称中
- **THEN** 结果中包含该选项项，不匹配的选项项被排除

#### Scenario: 删除选项项

- **WHEN** 管理员删除某选项项
- **THEN** 该选项项的 status 置为 1，不再出现在候选列表中，系统更新操作人与更新时间
- **AND** 该选项项仍可在管理列表中查询到

### Requirement: 选项项的启用与停用

系统 SHALL 允许管理员启用或停用选项项。停用的选项项 MUST NOT 出现在候选列表中，但 MUST 仍能被费用信息引用与保存——历史记录需要能继续编辑。重新启用后，该选项项 MUST 重新出现在候选列表中。

#### Scenario: 停用选项项

- **WHEN** 管理员停用某选项项
- **THEN** 该选项项不再出现在候选列表中

#### Scenario: 停用项仍可用于保存

- **WHEN** 用户保存一条引用了已停用选项项的费用信息
- **THEN** 系统接受并保存该记录

#### Scenario: 重新启用选项项

- **WHEN** 管理员重新启用某选项项
- **THEN** 该选项项重新出现在候选列表中

### Requirement: 删除前的影响提示

系统 SHALL 在删除选项项前告知管理员该选项被多少条费用信息引用。删除后，引用该选项的记录再次保存时 MUST 被拒绝并说明该选项已被删除。

#### Scenario: 删除前返回引用数量

- **WHEN** 管理员请求删除某选项项
- **THEN** 系统返回引用该选项的费用信息条数

#### Scenario: 删除后引用它的记录无法再保存

- **WHEN** 某选项项被软删除后，用户修改了引用它的费用信息并保存
- **THEN** 系统拒绝保存并说明该选项已被删除

### Requirement: 初始选项数据

系统 SHALL 预置一批初始选项项，使系统交付后可直接使用：费用代码预置 `DHLF`、`OCUC`、`OINSUR`，应付部门预置 `FIS`、`FES`、`FIA`、`FEA`，应付分支机构预置 `SHL`，币种预置 `USD`、`CNY`、`EUR`、`HKD`。应付对象与应收对象两项选项表不预置内容。

#### Scenario: 初始费用代码可用

- **WHEN** 用户选择费用代码
- **THEN** 候选列表中包含 `DHLF`、`OCUC`、`OINSUR`

#### Scenario: 初始部门与分支机构可用

- **WHEN** 用户首次打开费用信息录入界面并选择应付部门
- **THEN** 候选列表中包含 `FIS`、`FES`、`FIA`、`FEA`

#### Scenario: 初始币种可用

- **WHEN** 用户选择应付币种
- **THEN** 候选列表中包含 `USD`、`CNY`、`EUR`、`HKD`
