# Proposal

## Why

目前货运业务的费用信息散落在 Excel 与邮件里：应付多少、应收多少、付给谁、收自谁、什么币种，全靠人对着表格核。业务方需要的是一个能按货运订单号把一笔业务的两侧金额查清楚的地方，并且这个系统本身要有基本的用户管理与权限边界——谁能维护基础选项、谁能管理账号，得说清楚。

本次交付定位为**精简 MVP**：把「建货运订单 → 录费用信息 → 查订单的明细」这条主链路跑通，字段集与上游既有表结构对齐，便于日后直接与上游对账或同步。

## What Changes

- 新增一套**前后端分离**的工程结构：Python 后端提供 REST API，Vue 3 单页应用作为前端，两端通过 JSON over HTTP 通信、互不依赖部署。
- 新增 **MySQL** 数据库与可版本化的 schema 迁移。
- 新增**内部认证**：内部用户以**手机号**登录换取令牌——手机号既是唯一标识也是登录凭证，**不设密码与验证码**；账号一律由管理员开通，不提供自助注册。
- 新增**用户权限**：每个用户有权限级别 `admin` 或 `normal`。**admin 可维护六类选项数据、可管理用户；normal 两者都不行**，但两者都可以录入与查看货运订单与费用信息。
- 新增**用户管理页面**：管理员可列出、创建、修改用户（手机号、用户名称、权限级别），启用/停用账号，删除账号。首个管理员账号由命令行初始化。
- 新增**货运订单**：以 `Shipment Num.` 为唯一标识，由内部员工手工录入、全局唯一、比较不区分大小写。货运订单带一个业务状态（草稿 / 已确认 / 已完成 / 已取消），由单个内部用户一次动作推进，**不引入审批人、审批记录或审批链**；已确认与已取消是终态，但其下的费用信息仍可编辑。
- 新增**费用信息**：一条货运订单下可添加多条记录，每条记录**同时包含应付侧与应收侧**——应付侧有费用代码、应付部门、应付分支机构、应付币种、应付金额、应付对象，应收侧有应收币种、应收金额、应收对象，两侧均必填。任务码由所属货运订单自动带出。
- 新增**六类选项数据**：费用代码、应付部门、应付分支机构、币种、应付对象、应收对象，各自独立成表并提供**增删改查与启用停用**的管理页面（仅 admin）；页面上的下拉从这些表读取候选。费用信息的分类字段保存**选项内容本身**，录入时后端对照选项表校验取值存在且启用，防止手误。
- **本期不做汇率折算**：金额一律以各自币种计价，不设本地金额字段；**不提供金额区间筛选**。
- **金额只在明细里看，不做合计**：系统不提供应付/应收合计——列表页没有合计带，详情页也没有，列表接口与详情接口都不返回任何合计字段。货运订单列表只承担检索与定位（单号、费用信息条数、业务状态、操作人与时间），页面上**没有「查看」按钮**（点单号即进入详情）；详情页只有逐笔的费用信息明细。
- 前端提供登录页、货运订单列表页、货运订单详情页（含费用信息增删改）与用户管理页。

**明确不在本次范围内**（后续变更按需引入）：
- 跨货运订单的费用信息对账页与收支汇总页，及其对应的后端接口
- 汇率表与汇率折算计算
- 结算金额、支付状态、支付方式与支付时间（不在本期费用信息的字段清单内）
- 多级审批链与操作审计日志
- 库存与往来单位主数据管理
- 报表导出、税务计算与发票管理
- 部署编排与 CI/CD（本次仅提供本地开发环境）

## Capabilities

### New Capabilities

- `auth`: 内部用户凭手机号登录换取访问令牌（手机号即凭证，无密码无验证码）、令牌校验与失效处理、不存储任何凭据材料，以及对业务接口的访问控制与权限判定。本项目为对内系统，不提供自助注册。
- `user-management`: 内部用户的记录与生命周期——以手机号为唯一标识的用户字段与唯一性、用户列表查询、手机号/用户名称/权限级别的修改、启用停用与软删除，以及这些写操作的管理员权限要求。
- `shipment-management`: 货运订单这一业务容器的生命周期——货运订单号的录入与全局唯一性、创建、编辑、软删除、列表分页与多条件筛选、详情查看，以及业务状态的单级流转规则。
- `charge-info`: 费用信息这一记录单元——应付侧与应收侧成对结构的字段定义与必填校验、任务码的自动带出、选项引用的校验、记录的增删改与可见性规则。
- `amount-rules`: 金额与币种的取值口径——金额精度、应付与应收币种各自独立，以及不提供金额区间筛选。
- `option-lists`: 六类选项数据的维护——选项项的字段与唯一性、增删改查、启用停用、供录入选择与供管理使用的两种列表、删除前的影响提示、初始选项数据的预置，以及维护操作的管理员权限要求。

### Modified Capabilities

无。本项目当前没有任何既有 spec，本次为全新能力引入。

## Impact

- **新增后端**：Python 3.11+ / FastAPI / SQLAlchemy 2.0 / Alembic / Pydantic v2 / JWT 认证，pytest 测试。目录 `backend/`。
- **新增前端**：Vite / Vue 3 / TypeScript / Element Plus / Pinia / Vue Router / Axios，Vitest 测试。目录 `frontend/`。
- **新增数据库**：MySQL 8，字符集 `utf8mb4`；初始表 `users`、`shipments`、`charge_info`，以及六张选项表 `charge_codes`、`departments`、`branches`、`currencies`、`creditors`、`debtors`，迁移由 Alembic 管理。
- **新增本地开发环境**：docker-compose 提供 MySQL 8 实例，后端 `.env` 配置数据库连接与密钥。
- **对外接口**：全部为新增接口，无历史兼容性影响（项目当前无既有 API）。
- **依赖约束**：前端与后端仅通过 HTTP + JSON 契约耦合，任一端可独立替换。
